# Android QA and call-tracking fixes — 7 September 2026

## Outcome

Primary navigation passed on the Android emulator. A simulated incoming call was answered and ended using the app controls: the automatic notes popup showed **48s**, matching Android CallLog's **48 seconds**. Saving a note displayed it in Call details under Notes & tags, with Incoming / Connected and SIM information.

This is not a guarantee that every production integration or OEM phone behavior is verified. See the remaining coverage below.

## Changes

- Disconnect and later removal no longer extend the same call's end time.
- Queue the result at disconnect; return from the foreground call screen to the main app after removal.
- Handle a call already active when Telecom binds, and preserve the explicitly selected lead when matching the app's pending outgoing attempt.
- Persistent pending-result notification provides a route back when Android prevents a background popup. Notification permission is required to display it.
- Unassigned calls now have an automatic note dialog and can store call notes locally. Notes wait for lead assignment before dashboard sync because the existing server requires an assigned lead. Assignment attaches and queues those notes after the call-link event.
- Version 7 → 8 database migration preserves existing notes and permits a missing lead on a call note.
- System-log import uses durable per-row markers, serializes concurrent import calls, and processes complete timestamp groups oldest-first. Repeated calls cannot reuse an already reconciled call, and batches do not discard older or same-time rows.
- New imported call IDs are UUIDs compatible with the central server's validation.
- Short Home talk-time totals show seconds instead of rounding down to 0m.
- Guard against repeated Save submissions and tolerate a call-log read failure on activity resume.

## Environment and limitations

- Emulator: Resizable_Experimental, Android 17 preview (API 37.1 image).
- Isolated QA package: `com.callflow.qa`, fake backend, unreachable local API endpoint. The live app was force-stopped during the synthetic call so it could not import test data.
- The synthetic Android CallLog row (id 3, number 2025550100, date 1788791635288) was deleted after verification; query confirmed it absent. The disposable QA app retains its own test history and note.
- Initial navigation run failed because **com.android.systemui** was not responding. Cold boot and a repeated direct instrumentation run passed. Later APK installation encountered an ADB device-property timeout/offline connection. Final APK is built; installation of that final artifact in the emulator has not been confirmed.
- The final artifact uses application ID `com.callflow.app`, version 1.12.0/code 17, normal live endpoint and demo disabled. It is a debug-signed APK, not a Play Store release.
- The physical-phone installation warning from the initial screenshot is an Android permission restriction; these application changes do not bypass it.
